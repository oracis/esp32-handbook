芯片选型 / SELECTION

先认清型号：11 款芯片，只有 4 种活法

一句话决策

要屏幕/摄像头/语音 → S3；要 Matter/Thread → C6；只要联网够便宜 → C3；要比 2.4G 更干净的频段 → C5；电池供电压根不要 Wi-Fi → H2；7 寸以上的流畅界面 → P4。

型号之外还有 E22 等

乐鑫还有 ESP32-E22（Wi-Fi 6 协处理器）、H21/H4 等衍生型号，多为配套或专用场景，个人开发基本碰不到。看官方 SoC 列表比看淘宝标题可靠。PSRAM 不是标配：型号里的 N16R8 = 16 MB Flash + 8 MB PSRAM，买成 N8 就只有 Flash。

大模型 AGENT / ON-DEVICE

这块板子开始自己想了

2026 年最热的一条路。板上只负责听清、说清、执行，理解交给云。两条主线都已成熟：小智 AI 把语音入口和 MCP 控设备做成了标准件，ESP-Claw 干脆把 Agent Runtime 搬进了芯片。

33.7K★ / MIT
  • 离线唤醒 ESP-SR 自带中文唤醒词，唤醒不上云，隐私和延迟都省。
  • 链路 Opus 编码 + 流式 ASR → LLM → TTS，WebSocket 或 MQTT+UDP 二选一。

  • 上手 官方服务器注册就送 Qwen 实时模型额度，烧完固件配网就能说话。

ESP-Claw / espressif/esp-claw

2.4K★ / Apache-2.0
  • 聊天造物 在飞书/QQ/微信/Telegram 里说一句需求，模型生成 Lua 脚本下发到板子执行。
  • 三级路由 Lua 确定性规则走毫秒级；需要理解意图才升级到 LLM；更复杂的转云端模型。
  • MCP 双身份 既能当 Server 把传感器/执行器暴露给别的 Agent，也能当 Client 调外部工具。
  • 记忆本地 结构化记忆存板上（标签 + JSONL），隐私不上云，跨会话还记得你。
  • 门槛 要 Flash ≥ 8MB + PSRAM ≥ 8MB；S3 / P4 / C5 / S31 可用，网页一键烧录。

学习路线 / ROADMAP

八周路线：每周 6–8 小时，能走完

前提是 C 语言过关。指针和数组不熟的话，先补两周再来 —— 第 3 周就会卡死在那。路线刻意混用两条框架：先用 Arduino 拿反馈，再用 IDF 理解底层。

WEEK 1

环境 + 点亮

装 Arduino IDE 2.x 与 core 3.x，跑通 Blink 与串口打印。目标不是「亮灯」，是搞清楚「编译 → 烧录 → 串口」这条链断在哪一环。

WEEK 2

GPIO / 中断 / 定时器

按键消抖、外部中断、millis() 非阻塞计时。写一个不阻塞的呼吸灯，理解为什么不该用 delay()。

WEEK 3–4

总线：I2C / SPI / UART

接一颗 BME280 读温湿压，再用 SPI 点一块 ST7789 屏。逻辑分析仪（¥30 的克隆版即可）比读十篇文章有用。

WEEK 5

Wi-Fi + 一个云端

连 Wi-Fi 打 HTTP GET 拿天气，再推到 MQTT broker。学会处理重连、断网、DNS 失败 —— 这比「连上了」重要得多。

WEEK 6

进 ESP-IDF

装 IDF 5.5 LTS，用 idf.py 建工程、menuconfig、分区表。把第 5 周的 Wi-Fi 代码改成 IDF 版，体会事件循环和 FreeRTOS 任务的区别。

WEEK 7

FreeRTOS + 双核

两个任务、一个队列。Core 0 跑网络、Core 1 跑采样，用 xTaskCreatePinnedToCore 固定。这是从「能用」到「稳」的分水岭。

WEEK 8

OTA + 低功耗 + 收尾

加上 OTA 空中升级（记住要双 app 分区）、深度睡眠唤醒、看门狗。做完这一周，你已经能交付一台真设备了。

之后

选一个垂直方向深挖

LVGL 图形、ESP-ADF 音频、esp-matter 智能家居、ESP-NOW 自组网 —— 四条都能独立成职业方向。

产品实例 / IN THE WILD

别人已经做成了什么（可复刻）

下面 8 个都是完整可查的开源/在售项目，不是「想法」。每个都标了它真正解决的技术难点 —— 那才是复刻时值钱的部分。

CASE 01 / 智能家居

壁挂式 Home Assistant 控制面板

2.8″ 或 4.0″ 触摸屏跑磁贴界面，实时反映灯、风扇、窗帘状态，长按弹出亮度滑块。配套 3D 打印外壳，能嵌进标准欧标暗盒。

难点：开机直接进面板而不是桌面（Android 平板做不到这点），以及隐藏走线。屏幕是 ESP32-2432S028（CYD）或 ESP32-4848S040C_I。

CASE 02 / 商业终端

ESP32-P4 点餐机 / Kiosk

全本地运行：逻辑、菜单、媒体全在 SD 卡里，没有服务器、没有 broker、没有云。触屏点单、播放音视频，源码与 LVGL 模板开源。

难点：P4 没有硬件视频解码跑通用格式，作者用 Python 预转 MJPEG-in-AVI，靠 P4 的算力软解才做到 1024×600 全屏流畅。

CASE 03 / 支付硬件

UPI 自动售货机（动态二维码）

7 寸 CrowPanel 做交互面：选商品 → 按该笔金额生成动态二维码 → 付款成功后驱动热敏打印机出小票。完整的交易终端闭环。

难点：金额与二维码必须一一对应且不可复用，本质是把「支付状态机」跑在 MCU 上，容错比功能重要。

CASE 04 / 桌面硬件

EKOS 电子墨水看板（众筹在售）

橡木 + 阳极氧化铝外壳，BME280 测环境，4000 mAh 电池靠 light/deep sleep 调度撑数周。板载 HTTP 服务暴露 OpenAPI 文档化的本地 REST 接口，用 curl 就能改屏。

难点：选 IDF 而非 Arduino 正是为了功耗优化与底层外设控制；界面用 JSON 模板描述、LVGL 渲染，做 1-bit/灰阶优化。

CASE 05 / 全屋监测

P4 + 10.1″ 环境监测中枢

六个无线节点位，每个显示名称、电量、信号质量，本地存 24 小时历史曲线。数据不过厂商云，只有天气和 OTA 需要联网。

难点：「过期数据比没数据更误导人」—— 作者把最后上报时间直接摆在卡片上，而不是让屏幕停在几小时前的读数。

CASE 06 / AI 硬件

小智 AI 语音助手

国内最火的 ESP32 DIY 方向。裸核心板 30 元起，成品盒子 90 元。语音对话 + 表情屏，社区固件已相当成熟。

难点：别买 C3（无 PSRAM 跑不动）；N16R8 的 8 MB PSRAM 是硬门槛；麦克风与喇叭的选型决定了体验的一半。

CASE 07 / 能源

太阳能 / 电费看板

同时显示发电曲线、电池 SOC、分时电价和未来数小时调度计划。站着也能读清 —— 这是 1024×600 的信息密度下限。

难点：多层 LVGL 界面在 400 MHz 双核 + 大 PSRAM 下才不卡；它不是屏幕演示，是本来就必须存在的显示层。

CASE 08 / 入门练手

经典四件套：气象站 / 时钟 / 相机 / 掌机

BME280 气象站、NTP 网络时钟、ESP32-CAM 图传、8 位模拟器掌机。这四个几乎覆盖了所有基础外设，是被复刻最多的入门项目。

难点：不在功能，在于把它们做「稳」：断网自恢复、内存不泄漏、长时间运行不重启。

为什么给搜索页，不给商品链接。 淘宝商品 ID 换一次就变，收藏夹点开是「商品已下架」；搜索词永远有效，还能顺手比价、看销量。

怎么搜才准。 用「型号 + 关键参数」：esp32-s3 n16r8、st7789 2.4 spi、sht30 i2c。搜「ESP32 开发板」这种大词，前面全是九块九的玩具板。

裸芯片和模组走元件渠道。 立创商城（szlcsc.com）按料号能查库存和 datasheet；淘宝买模组更便宜，但版本和翻新件杂。

代码 / CODE

能直接抄的七段代码

Arduino core 3.x / ESP-IDF 5.5 语法。每段都是最小可用版本，复制过去改引脚就能跑。

wifi_hello.inoArduino core 3.x
// 连 Wi-Fi + 每 2 秒打印一次 IP 与 RSSI
#include <WiFi.h>

const char* SSID     = "your-ssid";
const char* PASSWORD = "your-pass";

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.setSleep(false);        // 关省电，延迟更稳
  WiFi.begin(SSID, PASSWORD);

  uint32_t t0 = millis();
  while (WiFi.status() != WL_CONNECTED) {
    delay(300);
    if (millis() - t0 > 15000) {   // 超时就重启，别死等
      Serial.println("wifi timeout, reboot");
      ESP.restart();
    }
  }
  Serial.printf("IP: %s\n", WiFi.localIP().toString().c_str());
}

void loop() {
  Serial.printf("RSSI %d dBm\n", WiFi.RSSI());
  delay(2000);
}
deep_sleep.ino定时唤醒，10 µA 级待机
// 采样 → 上报 → 睡 60 秒 → 循环
#define BUTTON_PIN 0

void setup() {
  Serial.begin(115200);
  delay(100);
  Serial.println("wake up");

  // 关键：把所有不用的外设彻底断电/隔离，否则漏电流会吃掉收益
  gpio_hold_en((gpio_num_t)BUTTON_PIN);
  esp_sleep_enable_ext0_wakeup((gpio_num_t)BUTTON_PIN, 0);
  esp_sleep_enable_timer_wakeup(60ULL * 1000000);
  esp_deep_sleep_start();   // 不会再返回 loop()
}

void loop() {}

踩坑 / PITFALLS

踩坑清单：这十条能省你两个周末

都是「现象 → 原因」的形式，方便你按症状反查。

!
烧完串口全是乱码。 波特率不对（日志默认 115200），或者供电不足导致芯片反复复位。换根能传数据的 USB 线，别用只能充电的。
!
一直停在 "Connecting..."。 手动按住 BOOT 再点 RESET 进下载模式；驱动没装（CH340 / CP210x / CH343 各不相同）也会这样。
!
GPIO 6–11 用了就死机。 这几根接着内部 SPI Flash，初代 ESP32 上绝对不能用。选引脚前先查对应型号的引脚表。
!
ADC 一开 Wi-Fi 读数就飘。 初代 ESP32 的 ADC2 与 Wi-Fi 共用硬件，联网时不可用。要测模拟量就用 ADC1（GPIO32–39）。
!
5V 接到了 3.3V 引脚。 当场烧。板子上有 5V/VIN 和 3V3 两个丝印，接线前看两遍。烧了别急着扔，多数是稳压器，能换。
!
OTA 一直失败。 默认分区表只有一个 app 分区，放不下第二份固件。要在 menuconfig 里改成 "Factory app, two OTA definitions"。
!
S3 买了 8MB PSRAM 却只剩一点。 8MB 是 octal 模式，必须显式开启（ESPHome 里 psram mode octal，IDF 里改 sdkconfig），否则默认不启用。
!
Wi-Fi 隔一会儿就断。 默认开了 modem sleep。要长连接就 WiFi.setSleep(false)，代价是功耗上升。另外关掉路由器里的「节能/802.11 省电」试试。
!
信号差、距离短。 板载 PCB 天线怕金属和手。装进金属盒必须换外置天线（IPEX/U.FL），并且天线净空区不能铺铜。
!
深度睡眠还是耗电几十 mA。 睡眠前没把外设断电、没做引脚 hold，传感器和 LDO 继续吃电。要逐项隔离测量，别信数据手册的 typ 值。
术语 / GLOSSARY

术语速查

看文档时被这些缩写卡住的话，回来查一眼。

SoC / 模组 / 开发板芯片本体 / 芯片+晶振+天线+屏蔽罩 / 模组+USB+稳压+排针。买「开发板」最省事，做产品用「模组」。
PSRAM片外伪静态内存。跑 LVGL、摄像头帧缓冲、语音缓冲必需。型号里 R8 就是 8MB。
NVS非易失存储，类似小 KV 数据库。存 Wi-Fi 密码、校准值、设备配置。
OTA空中升级。需要双 app 分区 + 回滚标记，别只做「能刷进去」。
Matter / Thread跨品牌智能家居应用层 / 低功耗网状网络层。C6 是单芯片同时支持的那颗。
ESP-NOW乐鑫私有 2.4G 点对点协议，不需要路由器，延迟毫秒级，适合遥控与传感网。
RMT红外/WS2812 用的精确脉冲外设。驱动灯带比软件延时可靠得多。
I2S数字音频总线。麦克风、功放、DAC 都走它。做语音项目第一个要搞懂的。
TWAIESP-IDF 里的 CAN 总线驱动名。车上/工业场景用。
eFuse一次性熔断位。安全启动、Flash 加密、MAC 都存在这，熔了不可逆。
看门狗 (TWDT)任务超时未喂狗就复位。长循环里记得 vTaskDelay 或喂狗。
menuconfigIDF 的图形化配置树，产出 sdkconfig。串口、分区表、组件开关都在这。
