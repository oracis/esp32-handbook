# 三方向与现有站点设定的比较

比较对象：`index.html`（现有上线版，截图 `baseline-desktop.png`）vs 三个方向初稿（dir-1 / dir-2 / dir-3）。
比较维度：骨架、色彩、字体、首屏、信息密度、用户路径、气质、代价。三版共用同一批真实内容（11 款 SoC / 2.4K–33.7K★ / 决策器 / 10 视频 / 23 资源 / 39 采购）。

---

## 一、与现有站点的逐维比较

| 维度 | 现有站点（基线） | 方向 1 · 数据表主导 | 方向 2 · 工业克制 | 方向 3 · 开发者文档 |
|---|---|---|---|---|
| **骨架** | 顶栏 13 项 → 左文右芯片 hero → 01–13 节单栏长页 | 细线顶栏 → 标题区 → **11 款 SoC 宽表居中** → 路线/决策器双栏 → 资料池 | 细线顶栏 → **一颗芯片特写占首屏大半** → 黑白交替 band（选型/路线/Agent）→ 极细线表格 | **顶栏 + 左 sticky 目录 + 右正文/代码并排** → 每个一级节一屏 → 章节末「下一步」 |
| **色彩** | 近黑 `#080a0d` + **五色并用**（红/琥珀/青/蓝/紫）+ 44px 网格 | PCB 墨绿 `#0E1A17` + 焊盘金 `#C9A24A` + 丝印白；红 `#E7352C` 仅警告一次 | 近黑 `#0B0D0C` + **零彩色 UI**，色彩只来自产品图与官方红状态 | 编辑器浅灰 `#F7F8FA` + 代码深墨 `#131820` + 乐鑫红点缀（唯一深色变浅色的版本） |
| **字体** | system sans + mono；h1 800 / 50px，标题重 | sans + JetBrains Mono；h1 800 / 56px，最重 | **全站 weight 300 细体** + mono 小标；标题 20px 极小，最轻 | sans + mono；正文 16px，文档式中等 |
| **首屏** | 标题左 + 芯片 SVG 右 + 5 数字格，读文字才知是工具站 | **3 秒看到选型表表头**，直接判断有没有自己要的芯片 | 一颗红 PCB 芯片特写占据视觉中心，像产品目录 | 左侧目录 + 右侧真实 `wifi_hello.ino` 代码面板 + 三步选型终端 |
| **信息密度** | 极高，13 节连续，标签多色抢焦点 | 高但有序：表格是锚，其余围绕它 | 中低：大留白 + 单 band 单主角，慢节奏 | 高但分区：目录/正文/代码三栏各司其职 |
| **用户路径** | 顶栏跳转 → 滚动找节 → 筛选 | 选型表 → 决策器 → 路线 → 资料 | 看产品 → band 逐个了解 → 细线表查参数 | 左侧目录直达 → 右栏查表/复制代码 → 下一节 |
| **气质** | 技术情报站（仪表盘 / 多色信号） | 考古精确的工具书（数据有尊严） | 工业展柜（静默 / 产品即主角） | 开发者文档（理性 / 可查可抄） |
| **相对现有** | 基线 | **同深色但收敛为 2 色**，把"多色标签站"变成"一张表" | **同深色但去除全部装饰**，把"情报站"变成"产品画廊" | **反转为浅色**，把"手册站"变成"文档站"——差异最大 |
| **改动代价** | — | 中：现有内容可复用，表格重排为主角 | 中高：需更好产品图支撑首屏，留白多 | 高：信息架构重做，左目录贯穿全页，i18n 需适配新结构 |

## 二、三版彼此的关键差异（不是换皮）

- **骨架不同**：宽表中心 / 横向 band 产品目录 / sticky 文档双栏。
- **色彩家族不同**：墨绿+金 / 近黑灰阶 / 浅灰编辑器。
- **字体气质不同**：重（800） / 极轻（300） / 中（文档）。
- **唯一大胆点不同**：dir-1 砍掉 hero 大图 / dir-2 全站零彩色 UI / dir-3 手册改文档架构。
- 三版都**没有**套用万能隐喻（不做地铁图、终端、报纸头版、老式道具）。

## 三、诚实标注

- 三版均为**方向初稿**：内容已用真实数据，但只覆盖核心节；选定后才做 13 节全量正式版与完整 i18n 迁移。
- 历史坑（`.rv` 不可嵌在 `data-l10n` 内）在正式版需继续遵守，初稿未做完整 i18n 迁移。
- 本机缺 Playwright/Pillow，`design_lint.py` 与 `ref_card.py measure` 的机器体检跳过，用 Chrome 截图 + 逐屏看图 + CSS 源码核对代替（详见 `polish-log.md`）。
- logo 只作题材/兼容性指称，不作官方背书（详见 `brand-spec.md`）。
