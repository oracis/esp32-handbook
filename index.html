第三条路线：断网也能听懂「把客厅灯调到 30%」

上面两条路线都要联网才能理解人话。2026 年多出一条纯端侧路线：Needle 2 是一个 45M 参数的工具调用模型，单个 14MB 二进制、28MB 会话内存，把一句话直接翻译成函数调用。它不聊天、不答常识，输出只有「调用列表」或「空列表」。

路线谁在理解断网时
① 小智 AI语音入口，云端大模型负责理解云端 ASR + LLM只剩唤醒
② ESP-Claw规则确定性执行，复杂的转云本地 Lua + 云 LLM本地规则
③ Needle 2一句话映射到预定义工具及其参数纯端侧 45M 模型可控设备

三条不是替代关系：① 适合要「聊天」的产品，② 适合确定性自动化，③ 适合「断网也要能听懂人话」的本地控制。

置信度：把「什么时候该上云」变成三行代码

Needle 每次返回都带一个校准过的 confidence。不用猜模型有没有把握——直接拿分数路由。

confidence_route.pyNeedle 2
# r = agent.complete(user_text)
if r["function_calls"] and r["confidence"] >= 0.7:
    execute(r["function_calls"])       # 有把握：直接执行
elif r["function_calls"] or r["suppressed_calls"]:
    confirm(r, r["reasoning"])       # 拿不准：把调用显示给人确认
else:
    escalate_to_cloud(user_text)          # 空调用：交给云端大模型

这六个坑是 AI 硬件专有的

!
麦克风和喇叭装在一个腔体里，一说话就啸叫。 S3/P4 用双麦 + AEC；单麦就物理隔开、做半双工（说话时不开麦）。
!
把 API Key 硬编码进固件。 固件能被 dump，别人刷你的量。走配网页写进 NVS，或干脆自建服务端代理。
!
Wi-Fi 省电模式让音频一顿一顿。 esp_wifi_set_ps(WIFI_PS_NONE)，语音场景别开 modem sleep。
!
在 GPIO35–37 上接麦克风。 S3 的 N16R8 开 Octal PSRAM 会占用这三个脚，接了就不出声。
!
历史对话不清，token 账单失控。 语音输入 80 元/百万 token，按轮数截断上下文，长记忆交给本地摘要。
!
模拟驻极体麦克风直接进 ADC。 底噪大、易被 Wi-Fi 干扰；换 INMP441 这类 I2S 数字麦，一句话解决。

一句话决策

要屏幕/摄像头/语音 → S3； 要 Matter/Thread → C6； 只要联网够便宜 → C3； 要比 2.4G 更干净的频段 → C5； 电池供电压根不要 Wi-Fi → H2； 7 寸以上的流畅界面 → P4。

被忽略的两个坑

PSRAM 不是标配。 型号里的 N16R8 = 16 MB Flash + 8 MB PSRAM， 跑 LVGL 大屏和语音必需；买成 N8 就只有 Flash。
P4 没有射频。 它是 CPU，不是 SoC，做联网得另配一颗。

型号之外还有 E22 等

乐鑫还有 ESP32-E22（Wi-Fi 6 协处理器）、H21/H4 等衍生型号， 多为配套或专用场景，个人开发基本碰不到。看官方 SoC 列表比看淘宝标题可靠。

四条路线：别再问「Arduino 还是 IDF」

真正的问题不是二选一，而是你处在哪个阶段。 截至 2026 年 11 月：ESP-IDF 最新稳定版 6.1（2026-08-27 发布）、LTS 分支 5.5.x（补丁 5.5.6）； Arduino-ESP32 core 已到 3.3.x 系列，底层就是 IDF 5.5.5。 两者早已不是两个世界。

ESP-IDF

官方 · 正路
CCMake+NinjaFreeRTOS
  • 芯片能力全开，OTA / 分区表 / 电源管理原生
  • 组件注册中心按需拉依赖
  • Blink 约 180 KB，比 Arduino 小一个数量级
适合：产品化、低功耗、多协议网关

Arduino core 3.x

最快出东西

  • 半小时点亮，第三方库生态无敌
  • 底层已是 IDF 5.5，性能差距很小
  • 代价：工程化能力弱、每次全量编译
适合：原型、教学、创客项目

PlatformIO

桥
VS Codeframework 一行切
  • 同一份工程，framework 改一行就在 IDF / Arduino 间切换
  • 能直接调 menuconfig，管依赖像 npm
  • 多板多环境并行构建
适合：不想被 IDE 绑架的人

MicroPython / ESPHome

不写 C
PythonYAML
  • REPL 改一行跑一行，验证外设极快
  • ESPHome 用 YAML 描述设备，接 Home Assistant 一把梭
  • 时序敏感场景和极致低功耗都不占优
适合：智能家居、算法验证、不碰编译链

版本这件事，别抄旧教程

网上大量教程基于 IDF 4.x / core 2.x，API 已经变过。 IDF 5.2 起官方主推新的 driver/i2c_master.h，旧的 driver/i2c.h 已标记弃用（6.0 起移除）； Arduino core 3.x 则把 ledcSetup/ledcAttachPin 换成了 ledcAttach(pin, freq, res)。 看到 #include <driver/i2c.h> 就知道这篇是四年前的了。 查版本的唯一去处是 release-notes.espressif.com 与 github.com/espressif/arduino-esp32/releases。

八周路线：每周 6–8 小时，能走完

前提是 C 语言过关。指针和数组不熟的话，先补两周再来 —— 第 3 周就会卡死在那。 路线刻意混用两条框架：先用 Arduino 拿反馈，再用 IDF 理解底层。

WEEK 1

环境 + 点亮

装 Arduino IDE 2.x 与 core 3.x，跑通 Blink 与串口打印。目标不是「亮灯」，是搞清楚「编译 → 烧录 → 串口」这条链断在哪一环。

WEEK 2

GPIO / 中断 / 定时器

按键消抖、外部中断、millis() 非阻塞计时。写一个不阻塞的呼吸灯，理解为什么不该用 delay()。

WEEK 3–4

总线：I2C / SPI / UART

接一颗 BME280 读温湿压，再用 SPI 点一块 ST7789 屏。逻辑分析仪（¥30 的克隆版即可）比读十篇文章有用。

WEEK 5

Wi-Fi + 一个云端

连 Wi-Fi 打 HTTP GET 拿天气，再推到 MQTT broker。学会处理重连、断网、DNS 失败 —— 这比「连上了」重要得多。

WEEK 6

进 ESP-IDF

装 IDF 5.5 LTS，用 idf.py 建工程、menuconfig、分区表。把第 5 周的 Wi-Fi 代码改成 IDF 版，体会事件循环和 FreeRTOS 任务的区别。

WEEK 7

FreeRTOS + 双核

两个任务、一个队列。Core 0 跑网络、Core 1 跑采样，用 xTaskCreatePinnedToCore 固定。这是从「能用」到「稳」的分水岭。

WEEK 8

OTA + 低功耗 + 收尾

加上 OTA 空中升级（记住要双 app 分区）、深度睡眠唤醒、看门狗。做完这一周，你已经能交付一台真设备了。

之后

选一个垂直方向深挖

LVGL 图形、ESP-ADF 音频、esp-matter 智能家居、ESP-NOW 自组网 —— 四条都能独立成职业方向。

// 连 Wi-Fi + 每 2 秒打印一次 IP 与 RSSI
#include <WiFi.h>

const char* SSID     = "your-ssid";
const char* PASSWORD = "your-pass";

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.setSleep(false);        // 关省电，延迟更稳
  WiFi.begin(SSID, PASSWORD);

  uint32_t t0 = millis();
  while (WiFi.status() != WL_CONNECTED) {
    delay(300);
    if (millis() - t0 > 15000) {   // 超时就重启，别死等
      Serial.println("wifi timeout, reboot");
      ESP.restart();
    }
  }
  Serial.printf("IP: %s\n", WiFi.localIP().toString().c_str());
}

void loop() {
  Serial.printf("RSSI %d dBm\n", WiFi.RSSI());
  delay(2000);
}

// 发送端：上电广播一条结构体
#include "esp_now.h"
#include "esp_wifi.h"

typedef struct { float temp; uint16_t seq; } pkt_t;
static const uint8_t PEER[6] = {0xFF,0xFF,0xFF,0xFF,0xFF,0xFF};

void app_main(void) {
  nvs_flash_init();
  esp_netif_init();
  esp_event_loop_create_default();
  esp_wifi_init(&wifi_init_cfg);
  esp_wifi_set_mode(WIFI_MODE_STA);
  esp_wifi_start();

  esp_now_init();
  esp_now_peer_info_t p = { .channel = 1, .encrypt = false };
  memcpy(p.peer_addr, PEER, 6);
  esp_now_add_peer(&p);            // 广播地址要显式加 peer

  pkt_t d = { .temp = 23.4f, .seq = 0 };
  for (;;) {
    esp_now_send(PEER, (uint8_t*)&d, sizeof d);
    d.seq++; vTaskDelay(pdMS_TO_TICKS(1000));
  }
}

#define BUTTON_PIN 0

void setup() {
  Serial.begin(115200);
  delay(100);
  Serial.println("wake up");

  // 这里做一次采样 + 联网上报，尽量在 2 秒内完成

  gpio_hold_en((gpio_num_t)BUTTON_PIN);

  esp_sleep_enable_timer_wakeup(60ULL * 1000000);
  esp_deep_sleep_start();   // 不会再返回 loop()
}

踩坑清单：这十条能省你两个周末

都是「现象 → 原因」的形式，方便你按症状反查。

!
烧完串口全是乱码。 波特率不对（日志默认 115200），或者供电不足导致芯片反复复位。换根能传数据的 USB 线，别用只能充电的。
!
一直停在 "Connecting..."。 手动按住 BOOT 再点 RESET 进下载模式；驱动没装（CH340 / CP210x / CH343 各不相同）也会这样。
!
GPIO 6–11 用了就死机。 这几根接着内部 SPI Flash，初代 ESP32 上绝对不能用。选引脚前先查对应型号的引脚表。
!
ADC 一开 Wi-Fi 读数就飘。 初代 ESP32 的 ADC2 与 Wi-Fi 共用硬件，联网时不可用。要测模拟量就用 ADC1（GPIO32–39）。
!
5V 接到了 3.3V 引脚。 当场烧。板子上有 5V/VIN 和 3V3 两个丝印，接线前看两遍。烧了别急着扔，多数是稳压器，能换。
!
OTA 一直失败。 默认分区表只有一个 app 分区，放不下第二份固件。要在 menuconfig 里改成 "Factory app, two OTA definitions"。
!
S3 买了 8MB PSRAM 却只剩一点。 8MB 是 octal 模式，必须显式开启（ESPHome 里 psram: mode: octal，IDF 里改 sdkconfig），否则默认不启用。
!
Wi-Fi 隔一会儿就断。 默认开了 modem sleep。要长连接就 WiFi.setSleep(false)，代价是功耗上升。另外关掉路由器里的「节能/802.11 省电」试试。
!
信号差、距离短。 板载 PCB 天线怕金属和手。装进金属盒必须换外置天线（IPEX/U.FL），并且天线净空区不能铺铜。
!
深度睡眠还是耗电几十 mA。 睡眠前没把外设断电、没做引脚 hold，传感器和 LDO 继续吃电。要逐项隔离测量，别信数据手册的 typ 值。

术语速查

看文档时被这些缩写卡住的话，回来查一眼。

SoC / 模组 / 开发板芯片本体 / 芯片+晶振+天线+屏蔽罩 / 模组+USB+稳压+排针。买「开发板」最省事，做产品用「模组」。
PSRAM片外伪静态内存。跑 LVGL、摄像头帧缓冲、语音缓冲必需。型号里 R8 就是 8MB。
NVS非易失存储，类似小 KV 数据库。存 Wi-Fi 密码、校准值、设备配置。
OTA空中升级。需要双 app 分区 + 回滚标记，别只做「能刷进去」。
Matter / Thread跨品牌智能家居应用层 / 低功耗网状网络层。C6 是单芯片同时支持的那颗。
ESP-NOW乐鑫私有 2.4G 点对点协议，不需要路由器，延迟毫秒级，适合遥控与传感网。
RMT红外/WS2812 用的精确脉冲外设。驱动灯带比软件延时可靠得多。
I2S数字音频总线。麦克风、功放、DAC 都走它。做语音项目第一个要搞懂的。
TWAIESP-IDF 里的 CAN 总线驱动名。车上/工业场景用。
eFuse一次性熔断位。安全启动、Flash 加密、MAC 都存在这，熔了不可逆。
看门狗 (TWDT)任务超时未喂狗就复位。长循环里记得 vTaskDelay 或喂狗。
menuconfigIDF 的图形化配置树，产出 sdkconfig。串口、分区表、组件开关都在这。
CQ2-bitNeedle 用的 2 位量化：不是训练完再压，而是从预训练阶段就按 2 位训练，所以 45M 参数能装进 14MB。
engram哈希 n-gram 查表，把一部分「记忆」从矩阵乘法里搬出来，按行 gather，解码时几乎不算 FLOPs。
confidence gating模型自带置信度分。高分直接执行，中等分给人确认，空调用就转到云端——端云分工的开关。
