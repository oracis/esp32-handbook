先认清型号：11 款芯片，只有 4 种活法

一句话决策
要屏幕/摄像头/语音 → S3；要 Matter/Thread → C6；只要联网够便宜 → C3；要比 2.4G 更干净的频段 → C5；电池供电压根不要 Wi-Fi → H2；7 寸以上的流畅界面 → P4。
被忽略的两个坑
PSRAM 不是标配。型号里的 N16R8 = 16 MB Flash + 8 MB PSRAM，跑 LVGL 大屏和语音必需；买成 N8 就只有 Flash。
P4 没有射频。它是 CPU，不是 SoC，做联网得另配一颗。
型号之外还有 E22 等
乐鑫还有 ESP32-E22（Wi-Fi 6 协处理器）、H21/H4 等衍生型号，多为配套或专用场景，个人开发基本碰不到。看官方 SoC 列表比看淘宝标题可靠。

四条路线：别再问「Arduino 还是 IDF」

真正的问题不是二选一，而是你处在哪个阶段。截至 2026 年 11 月：ESP-IDF 最新稳定版 6.1（2026-08-27 发布）、LTS 分支 5.5.x（补丁 5.5.6）；Arduino-ESP32 core 已到 3.3.x 系列，底层就是 IDF 5.5.5。两者早已不是两个世界。

ESP-IDF官方 · 正路
CCMake+NinjaFreeRTOS
  • 芯片能力全开，OTA / 分区表 / 电源管理原生
  • 组件注册中心按需拉依赖
  • Blink 约 180 KB，比 Arduino 小一个数量级
适合：产品化、低功耗、多协议网关
Arduino core 3.x最快出东西
C++setup/loop库最多
  • 半小时点亮，第三方库生态无敌
  • 底层已是 IDF 5.5，性能差距很小
  • 代价：工程化能力弱、每次全量编译
适合：原型、教学、创客项目
PlatformIO桥
VS Codeframework 一行切
  • 同一份工程，framework 改一行就在 IDF / Arduino 间切换
  • 能直接调 menuconfig，管依赖像 npm
  • 多板多环境并行构建
适合：不想被 IDE 绑架的人

  • REPL 改一行跑一行，验证外设极快
  • ESPHome 用 YAML 描述设备，接 Home Assistant 一把梭
  • 时序敏感场景和极致低功耗都不占优
适合：智能家居、算法验证、不碰编译链
八周路线：每周 6–8 小时，能走完

前提是 C 语言过关。指针和数组不熟的话，先补两周再来 —— 第 3 周就会卡死在那。路线刻意混用两条框架：先用 Arduino 拿反馈，再用 IDF 理解底层。

WEEK 1环境 + 点亮

装 Arduino IDE 2.x 与 core 3.x，跑通 Blink 与串口打印。目标不是「亮灯」，是搞清楚「编译 → 烧录 → 串口」这条链断在哪一环。

WEEK 2GPIO / 中断 / 定时器

按键消抖、外部中断、millis() 非阻塞计时。写一个不阻塞的呼吸灯，理解为什么不该用 delay()。

WEEK 3–4总线：I2C / SPI / UART

接一颗 BME280 读温湿压，再用 SPI 点一块 ST7789 屏。逻辑分析仪（¥30 的克隆版即可）比读十篇文章有用。

WEEK 5Wi-Fi + 一个云端

连 Wi-Fi 打 HTTP GET 拿天气，再推到 MQTT broker。学会处理重连、断网、DNS 失败 —— 这比「连上了」重要得多。

WEEK 6进 ESP-IDF

装 IDF 5.5 LTS，用 idf.py 建工程、menuconfig、分区表。把第 5 周的 Wi-Fi 代码改成 IDF 版，体会事件循环和 FreeRTOS 任务的区别。

WEEK 7FreeRTOS + 双核

两个任务、一个队列。Core 0 跑网络、Core 1 跑采样，用 xTaskCreatePinnedToCore 固定。这是从「能用」到「稳」的分水岭。

WEEK 8OTA + 低功耗 + 收尾

加上 OTA 空中升级（记住要双 app 分区）、深度睡眠唤醒、看门狗。做完这一周，你已经能交付一台真设备了。

之后选一个垂直方向深挖

LVGL 图形、ESP-ADF 音频、esp-matter 智能家居、ESP-NOW 自组网 —— 四条都能独立成职业方向。

大模型 Agent：这块板子开始自己想了

2026 年最热的一条路。板上只负责听清、说清、执行，理解交给云。两条主线都已成熟：小智 AI 把语音入口和 MCP 控设备做成了标准件，ESP-Claw 干脆把 Agent Runtime 搬进了芯片。

小智 AI · xiaozhi-esp3233.7K★ · MIT
  • 离线唤醒 ESP-SR 自带中文唤醒词，唤醒不上云，隐私和延迟都省。
  • 链路 Opus 编码 + 流式 ASR → LLM → TTS，WebSocket 或 MQTT+UDP 二选一。
  • MCP 双端 设备端控制音量、灯、舵机、GPIO；云端 MCP 接智能家居、搜索、桌面操作。
  • 硬件 已适配 70+ 开源硬件（S3-BOX3、CoreS3、微雪 AMOLED 等），C3/S3/P4 都能跑。
  • 上手 官方服务器注册就送 Qwen 实时模型额度，烧完固件配网就能说话。

ESP-Claw · espressif/esp-claw2.4K★ · Apache-2.0
  • 聊天造物 在飞书/QQ/微信/Telegram 里说一句需求，模型生成 Lua 脚本下发到板子执行。
  • 三级路由 Lua 确定性规则走毫秒级；需要理解意图才升级到 LLM；更复杂的转云端模型。
  • MCP 双身份 既能当 Server 把传感器/执行器暴露给别的 Agent，也能当 Client 调外部工具。
  • 记忆本地 结构化记忆存板上（标签 + JSONL），隐私不上云，跨会话还记得你。
  • 门槛 要 Flash ≥ 8MB + PSRAM ≥ 8MB；S3 / P4 / C5 / S31 可用，网页一键烧录。

墨水屏：驱动原理与残影物理特性 · 3 条 + 1 份文档

中文里少有的「自己做驱动」路线：不讲调库，而是从电泳粒子的运动讲到波形，再自己写驱动点亮一块 4.2 寸屏做成阅读器。残影不是 bug，是物理 —— 局刷波形短促，粒子停在中间态，累积到一定程度就擦不掉，只能靠全刷的往复驱动压回两极。通用策略是「局刷 5–10 次插一次全刷，或每小时一次」。

wifi_hello.inoArduino core 3.x
// 连 Wi-Fi + 每 2 秒打印一次 IP 与 RSSI
#include <WiFi.h>

const char* SSID     = "your-ssid";
const char* PASSWORD = "your-pass";

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.setSleep(false);        // 关省电，延迟更稳
  WiFi.begin(SSID, PASSWORD);

  uint32_t t0 = millis();
  while (WiFi.status() != WL_CONNECTED) {
    delay(300);
    if (millis() - t0 > 15000) {   // 超时就重启，别死等
      Serial.println("wifi timeout, reboot");
      ESP.restart();
    }
  }
  Serial.printf("IP: %s\n", WiFi.localIP().toString().c_str());
}

void loop() {
  Serial.printf("RSSI %d dBm\n", WiFi.RSSI());
  delay(2000);
}

踩坑清单：这十条能省你两个周末

都是「现象 → 原因」的形式，方便你按症状反查。

关键警告5V 接到了 3.3V 引脚 —— 当场烧。 板子上有 5V/VIN 和 3V3 两个丝印，接线前看两遍。烧了别急着扔，多数是稳压器，能换。这是全站唯一一次用红色，因为它是唯一一条会直接毁板的错误。
01烧完串口全是乱码。 波特率不对（日志默认 115200），或者供电不足导致芯片反复复位。换根能传数据的 USB 线，别用只能充电的。
02一直停在 "Connecting..."。 手动按住 BOOT 再点 RESET 进下载模式；驱动没装（CH340 / CP210x / CH343 各不相同）也会这样。
03GPIO 6–11 用了就死机。 这几根接着内部 SPI Flash，初代 ESP32 上绝对不能用。选引脚前先查对应型号的引脚表。
04ADC 一开 Wi-Fi 读数就飘。 初代 ESP32 的 ADC2 与 Wi-Fi 共用硬件，联网时不可用。要测模拟量就用 ADC1（GPIO32–39）。
05OTA 一直失败。 默认分区表只有一个 app 分区，放不下第二份固件。要在 menuconfig 里改成 "Factory app, two OTA definitions"。
06S3 买了 8MB PSRAM 却只剩一点。 8MB 是 octal 模式，必须显式开启（ESPHome 里 psram: mode: octal，IDF 里改 sdkconfig），否则默认不启用。
07Wi-Fi 隔一会儿就断。 默认开了 modem sleep。要长连接就 WiFi.setSleep(false)，代价是功耗上升。另外关掉路由器里的「节能/802.11 省电」试试。
08信号差、距离短。 板载 PCB 天线怕金属和手。装进金属盒必须换外置天线（IPEX/U.FL），并且天线净空区不能铺铜。
09深度睡眠还是耗电几十 mA。 睡眠前没把外设断电、没做引脚 hold，传感器和 LDO 继续吃电。要逐项隔离测量，别信数据手册的 typ 值。
10麦克风和喇叭装在一个腔体里，一说话就啸叫。 S3/P4 用双麦 + AEC；单麦就物理隔开、做半双工（说话时不开麦）。
11把 API Key 硬编码进固件。 固件能被 dump，别人刷你的量。走配网页写进 NVS，或干脆自建服务端代理。
12Wi-Fi 省电模式让音频一顿一顿。 esp_wifi_set_ps(WIFI_PS_NONE)，语音场景别开 modem sleep。

术语速查

看文档时被这些缩写卡住的话，回来查一眼。

SoC / 模组 / 开发板芯片本体 / 芯片+晶振+天线+屏蔽罩 / 模组+USB+稳压+排针。买「开发板」最省事，做产品用「模组」。
PSRAM片外伪静态内存。跑 LVGL、摄像头帧缓冲、语音缓冲必需。型号里 R8 就是 8MB。
NVS非易失存储，类似小 KV 数据库。存 Wi-Fi 密码、校准值、设备配置。
OTA空中升级。需要双 app 分区 + 回滚标记，别只做「能刷进去」。
Matter / Thread跨品牌智能家居应用层 / 低功耗网状网络层。C6 是单芯片同时支持的那颗。
ESP-NOW乐鑫私有 2.4G 点对点协议，不需要路由器，延迟毫秒级，适合遥控与传感网。
RMT红外/WS2812 用的精确脉冲外设。驱动灯带比软件延时可靠得多。
I2S数字音频总线。麦克风、功放、DAC 都走它。做语音项目第一个要搞懂的。
TWAIESP-IDF 里的 CAN 总线驱动名。车上/工业场景用。
eFuse一次性熔断位。安全启动、Flash 加密、MAC 都存在这，熔了不可逆。
看门狗 (TWDT)任务超时未喂狗就复位。长循环里记得 vTaskDelay 或喂狗。
menuconfigIDF 的图形化配置树，产出 sdkconfig。串口、分区表、组件开关都在这。
