## 卡 1 · 最佳设计师 A｜原研哉 + 数据库专家（「信息作为材料」）— 入选
- **逻辑与来源**：把「一本能查的工具书」当作设计对象，而非营销页。原研哉式「留白即信息」+ 数据库设计的精确性。
- **借的是什么**：只借一条机制 —— 「表格不是容器，是主角」：选型表占据页面中央最大面积，其他所有信息按与它的关系排布； header/footer 退到边缘，只用细线。不借原研哉的具体版式或字体。
- **不借的、自己长的**：不用无印良品的米白空无感。颜色从 ESP32 本身长：PCB 深墨绿 `#0E1A17` 为底、焊盘金 `#C9A24A` 为强调、丝印白 `#F2F0E9` 为正文；红 `#E7352C` 只在「关键警告」出现一次。字体：思源黑体 + JetBrains Mono（数字/型号），不用衬线。
- **主角素材**：放大到画面中心的可交互选型表（11 行 SoC），芯片 SVG 作为表格右上角的「标本图」而非装饰背景。
- **骨架**：顶部细线导航条 → 全宽标题区（一句判断，不上大图）→ 满幅选型表（主角）→ 左右分栏「路线 vs 决策器」→ 往下长页按「资料池」网格展开。
- **胆量花在哪**：首屏没有 hero 大图，直接把最硬的选型表推到眼前——让用户 3 秒判断「这站有没有我要的芯片」。
- **form 来自内容的哪里**：选型表是这站真正的产品；芯片家族的「数据兼容性」决定了版式必须精确、可扫读。

## 卡 2 · 最佳设计师 B｜Teenage Engineering 式工业克制（「硬件自己会说话」）— 入选
- **逻辑与来源**：真实作品 teenage.engineering（已 WebSearch 核实、截图 refs/ref-teenage.png 亲眼看过）。公开设计系统资料：纯黑 `#000` 画布、无圆角、重量 100–300 细字、无界面强调色，产品摄影承担 100% 情绪与色彩。
- **借的是什么**：**一条机制**——「界面零色彩竞争」：UI 只用灰阶+细线，所有饱和色只出现在产品本身与状态上；配合「一个产品一张特写、极大留白」的方形网格节奏。不借它的乐器产品、字形字体（它是定制 te-20）。目测：产品图占单屏 55–65% 面积，标题 20px/300 极小。
- **不借的、自己长的**：不用它的乐器摄影。颜色从芯片/PCB 长：近黑 `#0B0D0C` 底、灰阶 UI、产品图的红 PCB 与金引脚是唯一彩色；强调色用乐鑫官方红 `#E7352C` 且只给状态/警告。字体用系统细体（font-weight 300）+ mono 小标，中文回退思源黑体 Light。
- **主角素材**：高分辨率芯片/开发板特写（真图优先，缺则用现有精细 SVG 放大），一张图占首屏大半，像产品目录。
- **骨架**：细线顶栏 → 首屏「一个芯片特写 + 极小的型号文字 + 一行定位」→ 黑白交替的横向 band：选型 band / 路线 band / Agent band，每 band 一个主角物件 + 极简说明 → 长页表格保持极细线。
- **胆量花在哪**：全站零圆角、零阴影、零彩色 UI；只靠产品的真实颜色和巨大的留白建立气质。
- **form 来自内容的哪里**：硬件产品的物理性——引脚、丝印、PCB 是这题材独有的视觉资产，界面不该和它抢。

## 卡 3 · 现实参照｜Stripe Docs（「文档即产品」）— 入选
- **逻辑与来源**：真实作品 https://docs.stripe.com/（WebSearch 核实为开发者文档标杆、截图 refs/ref-stripe.png 亲眼看过）。
- **借的是什么**：**一条机制** —— 「左菜单 + 右内容 + 代码并排」：顶部一条主导航、左侧 sticky 目录、右侧正文与交互式代码块并置，截图中左列表约 230px / 右内容宽约 700px；首屏用淡点阵做区域底纹。不借它的紫色品牌色和金融题材。
- **不借的、自己长的**：不用 Stripe 紫/蓝渐变。颜色从开发环境长：编辑器浅灰 `#F7F8FA` 底 + 代码面板深墨 `#131820`，绿/橙终端色只用于状态；点缀用乐鑫红 `#E7352C`。字体用系统 sans + Mono，正文 16px。
- **主角素材**：可直接抄的代码片段面板（首屏右侧），和一个「3 步选型」的小型交互式 terminal（真实可点）。
- **骨架**：顶栏（13 导航压缩为 5 组 + 搜索） → 左侧 sticky 全文章节目录 → 右侧：文档式正文 / 代码与表格 / 内联注释 → 章节末尾「下一步」卡片。
- **胆量花在哪**：把一个「营销感手册站」彻底改造成开发者文档的信息架构，左侧目录贯穿全页。
- **form 来自内容的哪里**：这是一份工程师查资料用的参考手册，Stripe 式 sticky 目录 + 代码面板直接对应「查表 / 复制代码」的真实动作。

## 卡 4 · 秒数轮盘 A｜web #2 Neo-Brutalism（41 % 20 + 1 = 2）— 备选
- **逻辑与来源**：`references/design-styles.md` 网页区第 2 号；样张 `web/02-neo-brutalism.jpg` 已打开亲眼看。
- **借的是什么**：粗黑描边 + 硬偏移阴影做模块边界；高饱和纯色块分区（样张里紫/黄/粉大面积并置），标题字号与正文反差约 3:1；标签用小方框贴片。
- **不借的、自己长的**：不用它的紫/粉/黄配色与电影节题材；颜色改取芯片家族的识别色（红/青/金），但会与官方红规则冲突，需收敛为单色。
- **主角素材**：超大的「全家族 11 款」数字与模块网格里的芯片 SVG。
- **骨架**：黑底上高密度彩色模块拼贴，首屏左侧一个超大标题模块，右侧 5 个小信息模块。
- **胆量花在哪**：色块与粗描边的冲击力。
- **落选理由**：与「权威可查的工具书」气质冲突，色块抢信息，长时间查表会累；留作备选。

## 卡 5 · 秒数轮盘 B｜east #6 香港街招（41 % 12 + 1 = 6）— 备选
- **逻辑与来源**：east 区第 6 号，样张 `east/06-hk-street-signs.jpg` 已打开亲眼看。
- **借的是什么**：多层招牌叠压的密度感、竖排与横排混排、霓虹字外发光。
- **不借的、自己长的**：不用霓虹与繁体招牌；色彩改从芯片丝印取。
- **主角素材**：巨型竖排「ESP32」招牌字。
- **骨架**：层层叠压的文字招牌 + 底部价目表式采购清单。
- **胆量花在哪**：把采购清单做成霓虹价目板。
- **落选理由**：万能隐喻用力过头（去掉这个手法信息反而更清楚），且降低专业可信度；留作备选。

## 卡 6 · 现实参照 B｜Apple 产品页（refs/ref-apple.png）— 备选
- **逻辑与来源**：apple.com Vision Pro 产品页（截图亲眼看过，白底 + 单品特写 + 极小文案）。
- **借的是什么**：「一个产品占满屏 + 一行小字」的极端聚焦，图占 80% 面积。
- **不借的、自己长的**：不用 Apple 的白色调和奢华感。
- **主角素材**：单颗芯片巨大特写。
- **骨架**：全屏一图一文，往下逐屏单品。
- **落选理由**：站点核心是「11 款选型 + 大量可查资料」，不是卖一个产品；Apple 式聚焦会丢掉最重要的信息量；留作备选。
